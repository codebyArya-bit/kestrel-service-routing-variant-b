# Validation method
Use a chronological train/development/holdout split. Select features and review rules on development only; lock configuration and hashes before scoring holdout. Keep every row in all-row accuracy, including rows sent for human review. Separately report accepted coverage and accepted accuracy. Compare majority, declared policy and current routing baselines on identical rows. Include macro-F1, per-team errors, time/channel/product segments and repeated-input sensitivity. Closing team can be an imperfect proxy for customer intent. A high accepted-subset result does not establish high all-row accuracy. Public synthetic fixtures test implementation contracts, not operational quality.
